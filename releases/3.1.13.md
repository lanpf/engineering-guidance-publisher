# 3.1.13（2026-10-16）

## 范围

基于已发布 3.1.11（511c5c0），整合 3.1.12 草稿中的集合所有权与防御性复制约束，并收紧 NullSafe 集合/Map API 的使用边界、补齐构造器集合参数的 null 契约说明要求。以不可变 Git 标签 `3.1.13` 发布；3.1.12 仅保留草稿历史，不单独发布或打标签。权威政策源为 `standards/bp_java.md#集合所有权与防御性复制` 和 `standards/bp_validation.md#显式检查`。

## 政策变更

- `JAVA-COLLECTION-OWNERSHIP-001`（required / baseline，新增）：在保存外部可变集合或 Map 的实际边界复制，不依赖上游；临时读取、遍历或转发不要求复制，明确不可变的输入可复用，仅不可修改视图不足以隔离原容器变化。
- `JAVA-COLLECTION-COPY-MUTABILITY-001`（required / baseline，新增）：按对象状态契约选择独立可变副本或不可变副本，复制不等于一概冻结。
- `JAVA-COLLECTION-ELEMENT-ISOLATION-001`（required / baseline，新增）：需要隔离可变元素、嵌套容器或 Map key/value 时按契约处理，不机械深拷贝已不可变值。
- 退役 `JAVA-RECORD-002`，以以上三条通用规则覆盖 record 与普通类的集合保存责任、副本可变性和元素隔离；保留旧文本、分类及替代关系于 `3.1.13.rules.json`。
- `JAVA-CONTAINER-NULL-SEMANTICS-001`（required / topic，收紧）：仅当 null 与空容器均合法且语义等价时允许使用 NullSafe；必非 null、必非空及已由上游契约或对象不变量保证非 null 的容器均禁止使用，覆盖遍历、归一化和复制方法，前置校验不能豁免。
- `JAVA-CONSTRUCTOR-CONTAINER-NULLABILITY-001`（required / topic，新增）：构造器集合/Map 参数默认不允许 null；允许 null 时，构造器 Javadoc 的 `@param` 必须说明 null 的处理语义和适用条件。允许空容器不意味着允许 null。
- `JAVA-NULLSAFE-COPY-SELECTION-001`（default / topic，收紧）：仅在满足上述 null/empty 契约及技术异常语义时，优先使用 NullSafe 的不可变复制方法。

## Consumer 与工作流

相对于实际发布基线 3.1.11，代码合规性变更仅涉及 `develop-service` 的 `java-language.md` 和 `service-validation.md`：新增 4 条、修订 2 条、退役 1 条。其他持久规则 ID 保持稳定；Skill 名称、scope、blueprint 和引用文件路由不变。分层与校验文档仅回引 Java 的集合所有权政策，索引同步该范围。完整新增文本、修订前后文本及退役替代关系见 `3.1.13.rules.json`。

## 验证与同步

执行 catalog 验证、publisher 单元测试、构建、publisher Skill 安装及全部生成 Skill 校验后发布。用户指定同步并推送 gateway；consumer 同步前须保留项目专属指引及无关改动，对本地托管 Skill 改写与既有未推送提交须先解决范围确认，不能声称它们已被安全同步或推送。实际验证、发布提交、远端标签及 gateway 处理结果由本次交付报告确认。本次不实施 consumer 代码重构。
