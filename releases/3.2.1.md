# 3.2.1

基于已发布的 `3.2.0`，取消 Commons 工具的默认推荐，并明确测试镜像与生产保持一致、本地缓存只复用已选定镜像的边界。

## 通用工具与依赖

- 退役 `DEP-COMMONS-LANG3-BASELINE-001` 和 `JAVA-UTILITY-005`，不再要求或推荐 Commons Lang / Commons Collections 作为通用工具基线；旧 ID、原文与替代关系保留在 `3.2.1.rules.json`，不复用为其它含义。
- 新增 `DEP-MANAGED-DEPENDENCY-DECLARATION-001`（required / baseline），独立声明 dependencyManagement 不会自动引入依赖，实际使用库 API 的 module 按用途直接声明依赖。
- 修订 `JAVA-UTILITY-001`、`JAVA-UTILITY-006`，优先 JDK 和 module 已依赖的框架工具，复用要求只适用于已有依赖能提供的语义匹配工具；不为此强迫引入 Commons 或 Spring。
- 新增 `JAVA-SIMPLE-PREDICATE-DEPENDENCY-001`（required / baseline），不为避免直接调用 JDK 的简单字符串或集合判定而新增依赖或通用封装。
- 修订 `DEP-OVERLAP-001`、`JAVA-UTILITY-GUAVA-SCOPE-001`，清理 Commons 基线例外及回引。取消推荐不是全面禁用，不要求移除所有现有 Commons 用途；`Validate` 禁令及 Require / Assert 选择规则保持不变。

## 集成测试镜像

- 修订 `TEST-CONTAINER-IMAGE-001`（default / topic），由优先轻量变体改为优先官方标准变体，受生产一致性与目标架构约束。
- 新增 `TEST-CONTAINER-PRODUCTION-PARITY-001`（required / topic），测试数据库、中间件镜像的来源、版本和变体与生产约定一致，版本必须显式声明；不使用 latest、任意本地标签或轻量变体替代生产约定的标准镜像。
- 新增 `TEST-CONTAINER-LOCAL-CACHE-001`（default / topic），先确定符合生产约定的标准镜像，再复用该镜像的本地缓存。缺失、不满足选定版本或架构、或有明确更新要求时才拉取，不默认每次测试都强制拉取。
- 缓存不能改变镜像选择；manifest 的目标架构要求和多架构镜像偏好保持不变。复用镜像不等于复用生产容器或外部业务数据，测试环境隔离政策不变。

## 发布范围

涉及 `develop-service`（依赖、通用工具）和 `test-integration`（镜像）两个 consumer Skill：共新增 4 条、修订 5 条、退役 2 条规则，完整内容见 `3.2.1.rules.json`。Skill 名称、blueprint、路由及 scope 不变。

## 验证与同步

发布前运行规范校验、publisher 单元测试、构建、publisher Skill 安装及全部生成 Skill 校验；验证后发布不可变标签 `3.2.1`。用户确认 gateway 仅做本地规范同步，不提交或推送，保留业务工作区、暂存状态及既有未推送提交。不自动生成或实施重构计划。
