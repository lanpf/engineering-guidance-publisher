# 3.1.10（2026-10-09）

## 范围

基于已发布 3.1.9（16b6868），明确 `DOMAIN.md` 与 `RESPONSIBILITIES.md` 的语义边界，防止领域设计与服务章程变成代码实现说明。本版本以不可变 Git 标签 `3.1.10` 发布；consumer 工程按需同步，实际执行结果由本次发布与同步报告确认。

## 政策变更

- `DOMAIN.md` 维护本领域的概念、模型关系、不变量、决策、状态转换、用例、业务错误与事件；技术领域中的认证、签名、Header、配额等固有概念仍可保留。
- `RESPONSIBILITIES.md` 维护服务边界、对外承诺、协作契约、保证与限制及当前交付状态；对外包括服务、客户端、运维调用方和消息消费者。
- 两份文档均排除语言、类/record、注解、Getter/Setter、集合实现、类级调用链、装配和缓存优化等内部实现说明；项目专属技术决策独立维护，通用约定引用对应 BP，不堆入 README。
- 领域职责边界只说明业务决策归属，不规定 module、包、类或组件依赖；跨服务流程仅说明参与服务、顺序、交换数据及失败责任。
- 领域判定与协议表示分开，规则保持单一权威来源，通过摘要和链接引用；设计成立不等于已交付，历史验证不证明当前工作区通过。
- 领域正文描述当前认可的设计；职责文档维护当前状态，不累积开发流水账。章节结构为 advisory，替换实现后的语义稳定性审查为 default，其他新增约束为 required，均为 topic。

修订 ID：`DOCS-RESPONSIBILITY-SCOPE-001`、`DOCS-DOMAIN-001`、`DOCS-CONTRACT-SPLIT-001`。保留原 ID 的文档归属语义，收紧与澄清其边界；未重用退役 ID。引用的各节补充精确 source 标题，生成引用可追踪至源章节。
