# 3.3.0

本版面向采用内部 framework-* 的 Java 17、Maven、Spring 服务。从 3.2.1 升级后，开发与 PR 阶段可以直接验证真实运行边界。日常服务变更预读 8 份基础引用，共 88 条规则，原为 11 份、128 条。

## 消费工程的变化

- 开发阶段优先快速测试。修复事务、SQL、装配或中间件行为时，可随变更提交并运行最小集成回归。冒烟验证仍覆盖关键路径和部署环境。故障演练及人工判读场景保留专门文档。
- 单库并发写优先评估数据库能力。锁失效测试直接验证业务不变量。识别唯一约束冲突时，先判定错误类别，再确认具体约束及业务语义。
- 同步调用新增端到端等待预算、幂等重试与写请求结果未知时的恢复契约。
- 聚合错误按需登记单码或区间，同类容量耗尽时允许登记扩展前缀。已发布错误和既有预留块继续由原归属方维护。新分配取消固定首两个码位。
- 环境和运维参数优先外置。随代码演进的 SQL 映射、schema 和迁移可随版本制品交付和回滚。
- Lombok、MapStruct 和命名规则按任务加载。简单映射可以直接使用构造器或工厂。命名风格和工具偏好以默认约定为主。持久化查询与 MyBatis XML 的四条中文规则统一为主题级。

本版新增 3 个规则 ID，修订 63 个，退役 1 个。develop-service 和 test-integration 含合规规则变更。develop-distributed、develop-compensation、refactor-service 调整测试路由。Skill 名称和发布范围保持稳定。各 ID 的新旧正文、级别与所属 Skill 见[完整规则清单](3.3.0.rules.json)。

## 发布工具

- 18 份 BP 的每条政策与发布目录中的稳定 ID 关联。validate 检查双向覆盖、所属文档、强度和加载级别。
- 同步先检查本次新增纳管的 Skill。AGENTS.md、Skill 目录与 lock 作为一次变更提交。写入失败会恢复旧版本，中断的变更在重试时恢复。
- 构建在临时目录完成，成功后替换已识别的生成目录。新制品带文件清单。旧版制品可由 publisher lock 的摘要识别。
- 发布 CI 使用仓库既有的裸版本标签，如 3.3.0，并验证其与 catalog 版本一致。
