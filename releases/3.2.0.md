# 3.2.0

基于已发布的 `3.1.14`，对齐 framework `0.5.0-SNAPSHOT` 的 kernel 拆分与错误码契约。该版本号是工程规范版本，不改变 framework 构件版本。

## 政策变更

- **依赖方向**：新增 `DEP-KERNEL-FOUNDATION-001`、`DEP-KERNEL-MINIMAL-001`。`framework-kernel` 的生产代码只依赖 JDK；core 和其它 module 按需直接依赖 kernel。错误码、异常和 `Require` 不再要求引入 core；`NullSafe` 仍由 core 提供。
- **显式检查**：`JAVA-DEFENSIVE-CHECK-TOOL-001` 优先 kernel `Require`；只有 Require 不可用或不满足约束或异常契约，且 module 已依赖 Spring 时，才回退到 `Assert`。新增 `JAVA-VALIDATION-NO-COMMONS-VALIDATE-001`，在生产和测试代码禁用 Commons Lang `Validate`，不禁用 Commons Lang 的其它能力。
- **失败语义**：技术参数和技术状态分别使用 `Require` 参数检查方法与 `Require.state`；保留已承诺的 JDK 异常类型。业务检查保留业务异常供应器或显式守卫，业务异常基类迁至 kernel。NPE 禁令与 Bean Validation 规则不变。
- **错误码命名空间**：新增 `ERROR-NAMESPACE-OWNERSHIP-001`、`ERROR-EDGE-PASSTHROUGH-001`、`ERROR-FRAMEWORK-COMMON-001`。`FRAMEWORK`、`EDGE`、`BIZ` 的数字前缀分别为 `100–199`、`200–299`、`300–899`；错误按契约归属编码，透传保留原码。`FrameworkError` 仅保留三种通用错误，能力错误由所属模块定义。

## 兼容性与范围

前缀仍在部署体系内统一登记、分配；同一部署体系内不同服务不得共享 `BIZ` 前缀。同一归属的多个错误枚举可共享已分配的前缀，但必须统一本地码分配。

本版本涉及依赖坐标、Java 包路径及错误码命名空间；消费项目升级时需核对使用的 framework 版本及对外错误契约。`BIZ` 本地码段和已发布错误码不可变规则保持不变；规范升级不授权重编号、复用或改写既有公开错误码。

本次只修改 `develop-service` 的依赖、显式检查、服务校验和错误码规则：新增 6 条、修订 15 条，无退役规则。完整规则清单及修订前后文本见 `3.2.0.rules.json`；Skill blueprint、路由和 scope 不变。

## 验证与同步

发布前运行规范校验、publisher 单元测试、构建、publisher Skill 安装及生成 Skill 校验。发布后将托管规范同步到 `framework` 和 `framework-starter`，保留各自的项目指引；不提交或推送 consumer 仓库，也不自动启动重构。
