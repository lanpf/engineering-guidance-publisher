# 集成测试最佳实践

本文定义集成测试的阶段边界、独立 module、结构、文档和观测约束；集成测试只在测试冒烟阶段编写和执行。

## 集成测试

- **强制 · 主题**：集成测试只在测试冒烟阶段编写和执行，用于验证代码稳定后的跨 module 协作和真实基础设施行为；开发阶段测试边界遵循[单元测试最佳实践](bp_unit_testing.md#单元测试)。
- **强制 · 主题**：同时验证多个 module 的真实实现协作、完整自动装配或依赖真实数据库、中间件的场景属于集成测试；仅引用其他 module 的接口或 DTO 不因此构成集成测试。
- **强制 · 主题**：服务集成测试必须放入[服务分层最佳实践](bp_layered_service.md#模块职责)定义的独立测试 module，不得放入生产 module。
- **强制 · 主题**：服务工程的独立集成测试 module 及其依赖边界遵循[服务分层最佳实践](bp_layered_service.md#模块职责)。
- **默认 · 主题**：真实基础设施优先使用 Testcontainers 获得隔离且可重复的环境。
- **默认 · 主题**：集成测试使用容器时，优先选择官方维护的标准镜像变体，不以轻量变体作为默认选择；同时满足本节的生产一致性和目标架构要求。
- **强制 · 主题**：测试依赖的数据库、中间件等镜像，其发行来源、版本和变体必须与生产约定一致，并显式声明所选镜像版本；不得以 `latest`、任意本地标签或轻量变体替代生产约定的标准镜像。架构适配遵循本节 manifest 规则，不通过更换镜像变体规避。
- **默认 · 主题**：确定符合生产约定的标准镜像后，优先复用本地已有的相同镜像；本地缓存缺失、不满足所选版本或目标架构，或有明确更新要求时才拉取。不得默认强制每次测试都重新拉取，也不得为命中缓存改变已选定的镜像来源、版本或变体。
- **强制 · 主题**：必须确认镜像 manifest 支持本地开发环境和 CI 执行节点的目标架构。
- **默认 · 主题**：优先使用同时支持本地开发环境和 CI 执行节点的多架构镜像。
- **默认 · 主题**：集成测试场景保持自包含，容器、测试应用、配置、探针和生命周期管理优先放入对应 `*IT`。
- **强制 · 主题**：集成测试命名为 `*IT`；测试方法命名遵循[单元测试最佳实践](bp_unit_testing.md#单元测试)。
- **强制 · 主题**：集成测试由 Maven Failsafe 在 `integration-test` 和 `verify` 阶段执行。
- **默认 · 主题**：外部基础设施优先通过 `@Testcontainers` 和 `@Container` 管理。
- **强制 · 主题**：测试创建的应用上下文、执行器和其他资源必须在 `@AfterEach` 或等效生命周期边界释放。
- **强制 · 主题**：每个集成测试必须有同名文档，包含目标、条件、执行方式、手工观测步骤、观察入口和预期结果。
- **强制 · 主题**：独立测试 module 的根 `README.md` 只保留覆盖范围、环境要求、统一执行、报告位置和文档索引。
- **强制 · 主题**：详细集成测试场景文档放在独立测试 module 的 `docs/<测试类名>.md`。
- **强制 · 主题**：集成测试必须允许手工观察关键过程和最终结果；仅有自动断言或源码阅读不满足可观测要求。
