# 集成测试最佳实践

本文定义集成测试的阶段边界、独立 module、结构、文档和观测约束；集成测试只在测试冒烟阶段编写和执行。

## 集成测试

- 集成测试只在测试冒烟阶段编写和执行，用于验证代码稳定后的跨 module 协作和真实基础设施行为；开发阶段不得以集成测试替代单元测试。
- 跨 module、完整自动装配或依赖真实数据库、中间件的场景属于集成测试，不得放入生产 module。
- 服务工程的独立集成测试 module 及其依赖边界遵循[服务分层最佳实践](bp_layered_service.md#模块职责)。
- 真实基础设施优先使用 Testcontainers 获得隔离且可重复的环境。
- 集成测试使用容器时，在功能、版本和目标架构均满足测试要求的前提下，优先选择官方维护的轻量镜像变体；轻量变体缺少测试所需工具或能力时，才使用标准镜像。
- 必须确认镜像 manifest 支持本地开发环境和 CI 执行节点的目标架构，优先使用支持多架构的镜像。
- 集成测试场景保持自包含，容器、测试应用、配置、探针和生命周期管理优先放入对应 `*IT`。
- 集成测试命名为 `*IT`，由 Maven Failsafe 在 `integration-test` 和 `verify` 阶段执行；测试方法命名遵循[单元测试最佳实践](bp_unit_testing.md#单元测试)。
- 外部基础设施优先通过 `@Testcontainers` 和 `@Container` 管理；测试创建的应用上下文和执行器必须在 `@AfterEach` 释放。
- 每个集成测试必须有同名文档，包含目标、条件、执行方式、手工观测步骤、观察入口和预期结果。
- 独立测试 module 的根 `README.md` 只保留覆盖范围、环境要求、统一执行、报告位置和文档索引；详细场景放在 `docs/<测试类名>.md`。
- 集成测试必须允许手工观察关键过程和最终结果；仅有自动断言或源码阅读不满足可观测要求。
