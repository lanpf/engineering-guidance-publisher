# 单元测试最佳实践

本文定义单元测试与模块内契约测试的阶段边界、结构和编写约束；开发阶段只允许单元测试，集成测试遵循[集成测试最佳实践](bp_integration.md#集成测试)。

## 单元测试

- 开发阶段只编写和运行单元测试与模块内契约测试；代码尚未稳定，不得在开发阶段编写或运行集成测试，也不得以集成测试替代单元测试。
- 单元测试和模块内契约测试放在被测 module 的 `src/test`，就近验证类行为、模块协作和配置边界。
- 测试必须验证可观察行为和公共契约，不依赖非必要实现细节。
- 单元测试只能 Mock 被测对象注入的外部协作对象；不得对被测对象本身使用 partial mock 或 spy 替换被测逻辑。
- 仅在多个测试存在稳定且有意义的复用时抽取测试支持，不得仅为减少少量重复建立通用基类。
- 单元测试和模块契约测试命名为 `*Test`，由 Maven Surefire 在 `test` 阶段执行。
- 测试方法使用 `should<ExpectedBehavior>` 命名，直接描述被验证的可观察行为。
