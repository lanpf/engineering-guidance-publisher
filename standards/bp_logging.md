# 日志与敏感数据最佳实践

本文定义服务日志的级别选择、日志内容、链路上下文，以及敏感数据的定义和脱敏约束。

## 日志与敏感数据

- **强制 · 基础**：Logger 声明遵循[通用工具最佳实践](bp_common_tools.md#Lombok)；消息使用 SLF4J 参数化占位符，不得用字符串拼接构造文本。
- **强制 · 基础**：记录异常时，异常对象作为最后一个参数传入，不得拼入消息文本。
- **强制 · 基础**：日志必须按影响和处置需求选择下表中的级别，不仅按异常类型定级；正常幂等命中不因经过异常转换就升级为 `WARN`。

| 级别 | 使用条件 |
| --- | --- |
| `ERROR` | 需要人工介入的失败，例如重试耗尽、不可恢复错误、无法分类的完整性错误 |
| `WARN` | 值得关注的异常竞争、恢复或降级，即使已恢复也需关注其影响 |
| `INFO` | 正常幂等处理结果，以及关键业务动作、状态变化、外部交互的审计点 |
| `DEBUG` | 诊断信息 |

- **强制 · 基础**：生产环境默认关闭 `DEBUG`。
- **强制 · 基础**：日志必须携带可定位的业务上下文，例如用例或任务名、脱敏后的业务键、场景或分片标识。
- **强制 · 基础**：链路追踪上下文由框架统一注入，业务代码不得手工拼接 trace 字段。
- **强制 · 基础**：不得用日志替代指标、告警或链路追踪。
- **强制 · 基础**：高频重复事件的普通运行日志必须聚合、限频或采样，不得逐条输出 `INFO` 或通过升级为 `WARN` 绕过控制；聚合记录保留场景、时间窗口、次数和处理结果。
- **强制 · 基础**：明确要求逐条留痕的审计事件不得采样或丢弃，应进入受控的审计记录通道。
- **强制 · 基础**：敏感数据指口令、令牌、密钥、证书、身份证件号、手机号、银行卡号、生物特征、精确住址等个人敏感信息，以及完整的请求或响应报文。
- **强制 · 基础**：敏感数据不得以明文进入任何日志，包括消息文本、参数、MDC 和异常信息。
- **强制 · 基础**：确需在日志中关联敏感业务键时，必须使用集中实现的脱敏或不可逆摘要，不得在业务代码中散落实现。
- **强制 · 基础**：脱敏输出必须保留数据类型可辨识性并对主体掩码，例如手机号 `138****1234`；同一敏感类型在所有日志中使用一致的掩码格式。

## 验证

- **强制 · 主题**：冒烟阶段的集成测试必须覆盖集中脱敏工具对各类敏感数据的输出格式。
- **强制 · 主题**：冒烟阶段的日志配置验证必须证明生产级别下不输出 `DEBUG` 内容，且任何级别都不会明文输出敏感数据。
