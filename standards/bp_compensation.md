# 业务补偿与兜底最佳实践

本文定义业务补偿、对账、修复、清理和兜底流程的边界、幂等及恢复约束；XXL-JOB 只是可选的触发与运行技术之一。

## 业务补偿与兜底

- **强制 · 主题**：补偿流程只承载兜底、补偿、对账、修复、清理和批处理等辅助能力；核心实时业务链路不得依赖补偿按时执行才能成立。
- **强制 · 主题**：补偿流程可以由 XXL-JOB、消息、启动恢复或人工操作触发；触发入口只负责参数解析和框架适配，必须委托 application 用例或 infrastructure 通用补偿服务，不得直接实现领域规则。
- **强制 · 主题**：每个任务必须可重入、可重试和幂等；不得假设调度平台只触发一次。涉及数据写入的正确性保护遵循[数据持久化最佳实践](bp_persistence.md#并发写与事务)。
- **强制 · 主题**：同一资源需要由单个执行流处理时，必须通过稳定且互斥的资源归属方式收敛执行实例；分片键必须稳定映射到资源，无法仅靠分片保证互斥时使用分布式锁。无论触发平台提供何种路由或阻塞策略，数据写入仍必须具有独立的幂等或并发保护。
- **强制 · 主题**：批处理必须分页或分片并使用稳定排序游标，限制单批数量和单次运行时间；不得一次性加载全量数据或持有跨批次长事务。
- **强制 · 主题**：每批提交后记录可恢复检查点；失败重试必须从已提交边界继续，不得重复扩大副作用。
- **强制 · 主题**：任务参数只承载可校验的业务范围、游标或开关，不得包含密钥；参数缺失或非法必须快速失败。
- **强制 · 主题**：必须配置执行超时、告警、日志保留和失败处置；日志包含任务名、调度实例、分片、批次、处理数量和结果，但不得记录敏感数据，定义与脱敏遵循[日志与敏感数据最佳实践](bp_logging.md#日志与敏感数据)。

## XXL-JOB 触发实现

- **强制 · 主题**：使用 XXL-JOB 触发补偿流程时，scheduler 实现 module 只提供任务入口和框架适配，不得承载补偿规则或业务编排。
- **强制 · 主题**：`scheduler.xxljob.enabled`、admin 地址、namespace、端口和 access token 由环境配置；生产环境不得依赖 starter 默认值完成关键连接配置。

## 验证

- **强制 · 主题**：冒烟阶段的测试必须覆盖重复触发、部分批次失败后恢复、并发实例竞争、空数据和非法参数。
- **强制 · 主题**：使用 XXL-JOB 等实际运行技术时，冒烟阶段必须验证 executor 注册、namespace 隔离、超时及失败告警链路。
